# محوّل PDF إلى Word

موقع بواجهة عربية (RTL) يحوّل PDF إلى docx مع الحفاظ على الجداول والصور، وتحسينات خاصة بالنص العربي.

## التشغيل محلياً
```bash
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
# افتح http://localhost:8000
```

## الإعدادات (متغيرات البيئة)
| المتغير | الافتراضي | المعنى |
|---|---|---|
| `MAX_MB` | 15 | أقصى حجم للملف |
| `MAX_PAGES` | 60 | أقصى عدد صفحات |
| `RATE_LIMIT` | 10 | عدد التحويلات لكل IP |
| `RATE_WINDOW` | 3600 | مدة العدّ بالثواني |
| `MAX_CONCURRENT` | 2 | تحويلات متزامنة (ارفعها حسب قوة الخادم) |

## النشر
الأسهل: **Render** أو **Railway** أو **Fly.io** — اربط المستودع واختر Docker، وسيستخدم `Dockerfile` تلقائياً.
تنبيه: التحويل يستهلك معالجاً وذاكرة، فلا تعتمد على الخطط المجانية الضعيفة لحركة كبيرة.
مع الدومين: فعّل HTTPS من مزوّد الاستضافة (يلزم لتنزيل الملفات بأمان).

## ما يفعله الخادم
- يتحقق من أن الملف PDF حقيقي (وليس مجرد امتداد) ومن الحجم وعدد الصفحات.
- يرفض الملفات المحمية بكلمة مرور والممسوحة ضوئياً برسالة واضحة.
- يحذف الملفات المؤقتة فور انتهاء التحويل أو عند أي خطأ.
- يحدّ عدد التحويلات لكل عنوان IP.
- يصلح ترتيب «لا» المعكوس في النص العربي ويضع علامة RTL على الفقرات العربية.

## حدود معروفة (كن صريحاً بها مع المستخدمين)
- **الملفات الممسوحة ضوئياً** غير مدعومة (تحتاج OCR، مثل Tesseract بالعربية؛ هي الخطوة التالية المقترحة).
- بعض كلمات تحوي «لا» داخل الكلمة (مثل «استقلال») قد تبقى بحرفين مقلوبين في بعض ملفات PDF؛ المعالجة تصلح فقط الحالات الآمنة.
- التصاميم المعقدة جداً (نصوص متداخلة، خطوط نادرة) قد تحتاج تعديلاً بسيطاً بعد الفتح.
- حدّ المعدّل مخزَّن في الذاكرة: يكفي لخادم واحد، ويلزم Redis إن شغّلت عدة نسخ.

## ملاحظات قبل الإطلاق العام
- أضف صفحة «سياسة الخصوصية» تذكر أن الملفات تُحذف بعد التحويل.
- أضف Google Analytics أو Plausible لقياس الزيارات، وملف `robots.txt` وخريطة موقع للـ SEO.
